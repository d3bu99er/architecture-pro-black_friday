# 3. Архитектурная концепция шардирования

Основная идея решения:

1. **Географическая изоляция данных заказов и остатков**
   Операции создания заказа и списания товара должны выполняться локально внутри региона.

2. **Локальность каталога товаров**
   Поиск и фильтрация выполняются в пределах одного шарда.

3. **Коллокация корзины и пользователя**
   Все операции с корзиной выполняются внутри одного шарда.

# 4.1. Коллекция `products`

### Назначение

Хранение карточек товаров для витрины.

### Структура документа

```js
{
  _id: ObjectId("..."),        // product_id
  name: "Смартфон X",
  category: "electronics",
  price: 79990,
  attributes: {
    color: "black",
    size: "6.1"
  },
  created_at: ISODate("..."),
  updated_at: ISODate("...")
}
```

### Индексы

```js
db.products.createIndex({ category: 1, price: 1 })
db.products.createIndex({ name: "text" }) // опционально
```

### Стратегия размещения

Каталог товаров дублируется в каждом региональном шарде.

Это позволяет:

* выполнять поиск и фильтрацию локально;
* избежать scatter-gather запросов;
* обеспечить выполнение SLA по времени отклика.

Изменения каталога синхронизируются плановым процессом.

# 4.2. Коллекция `orders`

### Назначение

Хранение заказов пользователей.

### Структура документа

```js
{
  _id: ObjectId("..."),
  user_id: ObjectId("..."),
  location: "Moscow",
  created_at: ISODate("..."),
  status: "paid",
  items: [
    { product_id: ObjectId("..."), price: 79990, qty: 1 },
    { product_id: ObjectId("..."), price: 1990, qty: 2 }
  ],
  total_sum: 83970
}
```

### Индексы

```js
db.orders.createIndex({ location: 1, user_id: 1, created_at: -1 })
db.orders.createIndex({ location: 1, _id: 1 })
```

---

# 4.3. Коллекция `carts`

### Назначение

Хранение активных и завершённых корзин.

### Структура документа

```js
{
  _id: ObjectId("..."),
  user_id: ObjectId("..."),      // null для гостя
  session_id: "sess_123",
  location: "Moscow",
  status: "active",
  items: [
    { product_id: ObjectId("..."), quantity: 1 },
    { product_id: ObjectId("..."), quantity: 2 }
  ],
  created_at: ISODate("..."),
  updated_at: ISODate("..."),
  expires_at: ISODate("...")
}
```

### Индексы

```js
db.carts.createIndex({ session_id: 1, status: 1 })
db.carts.createIndex({ user_id: 1, status: 1 })
db.carts.createIndex({ expires_at: 1 }, { expireAfterSeconds: 0 })
```

# 5. Стратегия шардирования

---

## 5.1. Orders

**Шард-ключ:**

```js
{ location: 1, user_id: 1 }
```

### Обоснование

* Геозона обеспечивает локальность заказов.
* Добавление `user_id` предотвращает перегрузку одного шарда в крупных регионах.
* История заказов пользователя читается в пределах одного региона.
* Создание заказа и списание остатков выполняются локально.

---

## 5.2. Carts

**Шард-ключ (вариант с равномерным распределением):**

```js
{ location: 1, user_id: "hashed" }
```

### Обоснование

* Корзина размещается в том же регионе, что и пользователь.
* Хэширование снижает риск горячих шардов.
* Все операции с корзиной выполняются локально.

---

## 5.3. Products

Коллекция логически присутствует в каждом региональном шарде.

Формальное включение шардирования:

```js
sh.shardCollection("mobile_world.products", { _id: 1 })
```

Фактически каталог синхронизируется во все шарды управляемым процессом.

---

# 6. Команды MongoDB

## Включение шардирования

```js
use admin
sh.enableSharding("mobile_world")
```

## Шардирование коллекций

```js
sh.shardCollection("mobile_world.orders", { location: 1, user_id: 1 })

sh.shardCollection("mobile_world.carts", { location: 1, user_id: "hashed" })

sh.shardCollection("mobile_world.products", { _id: 1 })
```

# 7. Межрегиональные операции

* Пользователь оформляет заказ в конкретном регионе доставки.
* Межрегиональная комплектация не поддерживается.
* Для товаров из разных регионов требуется оформление отдельных заказов.
* История заказов может потребовать чтения из нескольких шардов.

---

# 8. Альтернативные варианты

### Вариант 1

Шардирование `products` по категориям без дублирования.

Недостатки:

* возможны межшардовые запросы при поиске;
* риск нарушения SLA.

---

### Вариант 2

Шардирование пользователей по id, товаров по категории.

Недостатки:

* корзина и каталог могут оказаться на разных шардах;
* больше межшардовых операций.

---

# 9. Ограничения и риски

## Недостатки

* Каталог товаров хранится в каждом региональном шарде.
* Невозможность объединённого заказа из нескольких регионов.

## Ограничения

* Заказы формируются в пределах одного региона доставки.

## Риски

* Межрегиональные операции могут требовать обращения к нескольким шардам.
* Возможны дополнительные задержки при агрегированных запросах по всем регионам.

---

# 10. Вывод

Предложенная стратегия:

* обеспечивает локальность критичных операций;
* минимизирует межшардовые транзакции;
* позволяет выдержать требования по производительности;
* снижает риск горячих шардов;
* масштабируется по регионам.
